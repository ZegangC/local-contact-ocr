# 分层验证与结果

日期：2026-11-04。下面三类结果分别报告，不能把它们相加或互相替代。

## A. 原本地原型的历史小试

此前两个保留任务共9个不同OCR身份标识，其中8条电话栏为空、1条有号码。只读核对时数据库、JSON和Excel一致；任务当时均为paused。没有对2000+全量做验收，也没有足够非空号码样本推导精度。真实记录与截图未公开。

## B. 公开版规则与恢复

33项检查覆盖昵称/备注、缺身份、空字段与缺区域、双读数分歧、低置信度、异常长度、多号码、长备注、同名/冲突、停止、任务指纹、保存/导出失败、合成跨屏和导航停滞；另验证expected答案注解不会驱动字段解析。运行测试不调用实际桌面输入。

默认重放7个虚构观察（包含1个重复）：首轮提交2条后暂停；显式使用修正观察并重开数据库，最终6条唯一记录。断点、事件和导出来自实际本地程序运行，动画据此渲染。屏幕编号是重放元数据；像素级跨屏导航在独立假桌面测试中验证，不能称为实时全链路操作录像。

## C. 真实本地模型对合成图片的识别

使用rapidocr-onnxruntime 1.4.4、CPU、系统中文字体；每张原色与反色分别识别，字段不同或数字置信度不足时保留未知。输入由代码生成，不是私人截图。

| 合成面板 | 电话字段 | 备注字段 | 解释 |
| --- | --- | --- | --- |
| 单个数字 | 精确匹配 | 精确匹配 | 前导零保留 |
| 完整空字段 | 正确为空 | 精确匹配 | 有完整空字段证据 |
| 多个数字 | 精确匹配 | 精确匹配 | 多值保留 |
| 异常长度 | 精确匹配 | 精确匹配 | 未擅自删位 |
| 缺下边界 | 待核对，符合预期 | 精确匹配 | 负例，不计入完整字段精确匹配分母 |
| 模糊图 | 待核对，未精确恢复 | 待核对，未精确恢复 | 保留失败，不强行选一个结果 |
| 长备注 | 精确匹配 | 精确匹配 | 多行内容 |

共7组；6组字段完整样本中，电话精确匹配5/6、备注精确匹配5/6；2组电话待核对（缺边界、模糊），本小样本误判为空0。原始聚合结果见[ocr-evaluation.json](../artifacts/ocr-evaluation.json)。这是单机合成面板结果，不是“微信准确率83.3%”；测试数字、字体与真实界面分布不同。
