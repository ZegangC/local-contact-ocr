# 三分钟演示讲解

## 先看约14秒合成动画

README的动画及artifacts/demo-report.html展示：读取虚构资料 → 保存2条 → 缺字段暂停 → 重开数据库 → 显式修正观察后续跑 → 6条唯一结果。

## 第一分钟：解释问题

不是只看识别到了几位数字，而是能否区分昵称/备注、空字段/未知，以及中断时已经保存了什么。指出图中所有名字、身份和数字都是生成的，动画不是实际微信录像。

## 第二分钟：运行核心路径

运行python demo.py。查看first_pass的2条和paused，再看恢复后的6条与deduplicated事件。打开该次输出目录，JSON、CSV、Excel是合成数据的真实文件；数据库不是动画中的占位数。

修正观察来自夹具预先提供的repaired字段，恢复时明确启用；没有声称程序能自动补出缺失信息。结束状态只针对夹具范围，不是全通讯录完成。

## 第三分钟：讲验证和局限

运行测试说明导航、停止与恢复使用假桌面和合成像素。实际本地OCR由独立评估脚本执行，报告包含模糊样本待核对的失败，而非展示一个“全绿准确率”。最后说明原型小样本、公开版和真实全量验收是三件不同的事。

建议准备回答：为什么空白不能直接记没有；同名如何去重；导出被占用会不会丢进度；两个OCR结果相同是否就正确；到了可见末尾为什么仍不能宣布全量完成；个人提出和修改了哪些规则、AI辅助了哪些实现。
