# 案例：让联系人资料整理遇到不确定时能停下来

2026-11-04回顾与公开版整理。作者Zegang Cui，AI辅助开发、文档与测试；不虚构团队规模、工时收益或用户研究。

## 概览

原型尝试整理本地可见联系人资料，后来形成独立程序，包含OCR、逐条保存、暂停和恢复。作品集版本进一步用合成输入替代私人截图，使读者无需登录真实账号即可复核关键规则。

## 问题

昵称与备注容易混淆；没有识别到电话可能是空值，也可能是区域缺失或数字模糊。桌面任务还会因焦点、窗口和导航变化中断。如果只追求继续运行，会把未知写成没有，或中断后重复处理。

## 过程与选择

根据原型记录，曾遇到缩小截图导致数字分歧、弹窗与主窗口坐标不同、列表不响应预期按键等问题。处理方向是使用原始像素、区分资料区块、保留异常数字，并在无法确认时暂停。公开版保留相关判断与像素导航规则，但不包含实时Windows操作器。

本次作品准备再做三项选择：以虚构界面和OCR读数替代私有夹具；把图像识别效果和流程规则分开测量；用真实的本地数据库恢复结果生成合成演示，而不把动画当现场录像。

## 方案

用稳定身份区分同名记录，SQLite逐条提交，状态记录下一个观察位置；相同身份不同内容暂停。缺少区域、两次读数不一致或低置信度时，不自动选一个值。恢复时检查输入指纹，并要求操作者显式提供修正观察。

## 结果

原型历史9条记录只支持小批量流程存在，其中1条非空电话，未全量验收。本公开版33项离线检查通过，7个虚构观察在暂停/恢复后保存6条唯一记录。真实本地OCR另测7组生成图片，6组完整字段中电话精确匹配5组；模糊样本保留失败并待核对。

这些结果说明部分规则可复验，不证明真实通讯录精度、通用Agent能力或商业收益。公开文件没有真实联系人，未将原任务扩大为新的实时采集。

## 复盘

最值得继续验证的是：谨慎拒识是否真的减少错误写入、跨布局与复杂内容的失败分布、崩溃恢复的一致性。下一步优先固定多样样本和人工标注，再考虑规模；不为“Agent”名称增加无必要的大模型调用。
